# 产品定义

## 1. 产品愿景

让不懂设计和 PowerPoint 自动化的用户，只需用大白话说明目的并提供材料，就能得到一份内容可信、视觉一致、可继续编辑、可直接演示的 PPTX，并能通过后续对话精确修改。

## 2. 目标用户

- 需要快速完成汇报的学生、教师和研究人员。
- 需要制作周报、方案、复盘和经营汇报的职场用户。
- 有固定品牌和模板要求、但缺少专职设计资源的小团队。
- 希望把文档、表格或旧演示文稿转成新演示文稿的用户。

## 3. 核心问题

现有“一句话生成 PPT”工具常见问题：

- 只生成一次，后续修改会让整份内容漂移。
- 生成整页图片，下载后几乎不能编辑。
- 网页预览好看，但导出的 PPTX 字体、换行或位置不同。
- 没有基于用户材料，容易编造数字和结论。
- 缺少大纲确认、版本历史和失败回退。

本产品以结构化演示文稿状态、确定性布局和真实文件预览解决这些问题。

## 4. MVP 用户旅程

1. 用户新建项目并输入大白话需求。
2. 用户可选上传 PDF、DOCX、PPTX、XLSX、Markdown、文本或图片。
3. 系统识别受众、目的、页数、语言和视觉方向；仅在关键信息缺失时追问。
4. 系统生成逐页大纲，用户确认或修改。
5. 系统生成可编辑 PPTX，并展示由该 PPTX 实际渲染出的页面预览。
6. 用户继续输入局部修改，例如：
   - “第 3 页只保留三个要点。”
   - “把第 5 页改成时间轴。”
   - “整份换成深蓝色，但不要改变内容。”
   - “在结论前加一页风险分析。”
7. 系统生成新版本；用户可查看、下载或回退。

## 5. MVP 功能范围

### 5.1 必须实现

- 仅凭自然语言创建一份演示文稿。
- 接受 PDF、DOCX、PPTX、XLSX、Markdown、纯文本和常见图片格式。
- 在生成 PPTX 前展示可编辑/可确认的大纲。
- 支持 16:9 中文演示文稿，默认使用 Windows 常见中文字体。
- 支持以下页面意图：
  - 封面；
  - 章节页；
  - 要点页；
  - 双栏页；
  - 图文页；
  - 指标卡；
  - 时间轴；
  - 基础图表；
  - 结束页。
- 使用原生文字、形状、图片、表格和常用图表生成可编辑 PPTX。
- 显示从最终 PPTX 渲染得到的 PNG 预览。
- 通过自然语言修改主题、页面内容、布局和顺序。
- 为每次成功修改保存版本并支持回退。
- 在下载前执行内容容量、资源、文件完整性和页数检查。
- 保留材料来源 ID，使关键结论可以追溯到用户材料。

### 5.2 MVP 不包含

- 多人实时协作、评论和权限系统。
- 自由拖拽的专业画布编辑器。
- 任意第三方 PPTX 的完全无损对象级编辑。
- 复杂动画、转场、SmartArt、宏和嵌入式对象。
- 企业级数据库、消息队列、对象存储和多租户。
- 自动联网研究作为默认能力。
- 多 Agent 自主讨论或开放式工具执行。
- 移动端原生应用。

## 6. 产品行为规则

- 缺少非关键参数时使用合理默认值；只有会显著改变结果时才追问。
- 先确认大纲，再生成完整文件。
- 一页聚焦一个核心结论，文字容量受布局限制。
- 用户材料优先于模型常识；没有依据的数字不得编造。
- 用户上传图片优先于图库和 AI 生图。
- 修改指令只影响明确目标；未命中的页面保持不变。
- 生成或修改失败时保留上一成功版本。
- 预览失败不能伪装成功；应允许用户查看错误并在安全时下载已通过文件检查的 PPTX。
- 不把整页位图包装成“可编辑 PPTX”。

## 7. MVP 默认值

| 项目 | 默认值 |
|---|---|
| 画面比例 | 16:9 |
| 语言 | 简体中文 |
| 字体 | Microsoft YaHei，缺失时使用可配置后备字体 |
| 页数 | 8 页；用户要求优先 |
| 主题 | 蓝白商务 |
| 每页要点 | 3～6 个 |
| 版本策略 | 每次成功生成或修改创建不可变版本 |
| 文件格式 | PPTX；预览中间产物为 PDF/PNG |

## 8. 成功标准

### 8.1 核心闭环

- 从空项目到可下载 PPTX 无需手写代码或编辑 JSON。
- 使用固定测试请求可生成 6～10 页演示文稿。
- 至少完成一次指定页面修改、一次主题修改和一次回退。
- PowerPoint 和 WPS 能无修复提示地打开输出文件。

### 8.2 内容与可编辑性

- 标题、正文、形状、表格和支持的图表可单独编辑。
- 用户素材中的关键数字不被无依据改写。
- 未被修改指令命中的页面，其结构化内容保持一致。

### 8.3 视觉与预览

- 预览页数与 PPTX 页数一致。
- 无明显文字越界、图片拉伸、空白必需区域或字体乱码。
- 预览来自当前版本 PPTX 的实际渲染结果。

## 9. 未来方向

MVP 完成后再评估：

- React Konva 自由画布；
- FastAPI 服务化；
- PptxGenJS 渲染器；
- 企业模板与品牌包；
- 现有 PPTX 增量编辑；
- 图片检索、生图和视觉模型质检；
- PostgreSQL、对象存储与任务队列；
- 协作、权限和私有化部署。

未来能力必须保持与 `DeckSpec` 和 `PatchPlan` 合同兼容，或通过明确版本迁移实现。
